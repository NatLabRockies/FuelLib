Source Code

This page provides an overview of the source code available at github.com/NatLabRockies/FuelLib.

FuelLib File Organization

  • docs: directory containing the documentation source files

  • fuellib: main package directory containing:

    • fuel: subpackage containing the Fuel class (re-exported as fuellib.Fuel)

      • core.py: core Fuel class for Group Contribution Method calculations, including loading of GCxGC data and matching of compounds to the reference data tables, plus deprecated aliases of the pre-comps/mix API

      • components.py: Components class (Fuel.comps) with the per-component properties (critical properties, reference-only and structural properties) and temperature-dependent methods

      • mixture.py: Mixture class (Fuel.mix) with the composition conversions and mixture-property methods

    • utils: subpackage with shared utilities

      • constants.py: physical constants and reference values (Boltzmann, Avogadro, gas constant, standard temperature, and air properties)

      • utility.py: utility functions for mixing rules, droplet calculations, and Lennard-Jones conversions (re-exported as fuellib.utility)

      • types.py: unit-aware type aliases and the Units registry

      • plotting.py: functions to plot fuel composition, mixture properties, and simulated D86 distillation curves (re-exported as fuellib.plotting)

      • color_maps.py: the fl_blue_4 and fl_pastel_18 colormaps (registered with Matplotlib) and the colors of specific fuels

    • gcm: subpackage implementing the Group Contribution Method (GCM) abstraction

      • core.py: GCM/GCMRegistry classes for registering and evaluating property functions

      • gani.py: Constantinou-Gani (and extended) property implementations registered against the gani GCM

      • gani.csv: group-contribution coefficient table used by gani.py

      • boehm.py: Boehm (2022) fusion-entropy (dS_fus) implementation registered against the boehm GCM; hydrocarbon families are read from ref_compounds.csv via the fuel’s components_data

      • boehm.csv: per-family dS_fus parameters used by boehm.py

      • nannoolal.py: Nannoolal et al. (2009) viscosity group contributions (dBv, Tv) registered against the nannoolal GCM, and automated SMILES decomposition into Nannoolal groups

      • nannoolal.csv: group-contribution coefficient table used by nannoolal.py

      • unifac.py: UNIFAC 2.0 (Hayer et al., 2025) activity coefficients, with the compound volume and surface parameters (R, Q) registered against the unifac GCM, and automated SMILES decomposition into UNIFAC hydrocarbon subgroups

      • unifac.csv: UNIFAC subgroup table (main group, R, Q) used by unifac.py

      • unifac_amn.csv: UNIFAC 2.0 main-group interaction parameters a_mn (K) used by unifac.py

    • correlate: subpackage with correlation functions used to compute temperature-dependent properties of components and mixtures

      • components.py: correlations for individual compound properties (e.g. density, viscosity, vapor pressure, surface tension, thermal conductivity, flash point, lower heating value)

      • mixture.py: correlations for mixture properties computed from component properties and mixing rules (e.g. density, viscosity, freeze point, flash point, heat of combustion, yield sooting index, derived cetane number)

      • helpers.py: shared helper functions for mixing rules and mass/mole fraction conversions

    • simulate: subpackage with simulations of fuel tests

      • distillation/greenfield.py: ASTM D86 distillation curve model of Greenfield et al. (1998) (see Simulated Distillation)

    • rdk: subpackage with RDKit-based molecular utilities

      • mol.py: functions for instantiating RDKit Mol objects from SMILES/InChI strings and for computing molecular formulas, atom counts, structural checks (aromaticity, rings, fused rings, aromatic ring counts, double bonds, branching), and molecular weight

    • data: directory containing fuel data and reference data

      • _data_locator.py: internal module for locating and validating fuel data directories

      • _reference_data.py: internal module for loading the reference tables and merging custom tables found in a fuel data directory

      • ref_compounds.csv: reference compounds (Family, Carbon Number, Reference Compound, SMILES) and their optional measured properties ({Property}_Value, _Error, _Units, _Source, _Notes)

      • ref_gani.csv: functional group decompositions of the reference compounds

      • ref_nannoolal.csv: Nannoolal group decompositions of the reference compounds

      • ref_unifac.csv: UNIFAC subgroup decompositions of the reference compounds

      • gc_data: directory containing a collection of GCxGC compositional data by weight percentages ({fuel_name}.csv)

      • properties_data: directory containing measurement or predicted data used for validation

      • fuel_metadata.yaml: YAML file with source information and other optional metadata for each fuel (loaded into Fuel.metadata)

    • exporters: subpackage with CLI exporters for generating fuel properties

      • converge.py: exporter for Converge CFD simulations (CLI: fl-export-converge)

      • pele.py: exporter for PelePhysics simulations (CLI: fl-export-pele)

    • cli: subpackage with command-line interface tools for data conversion and analysis

      • convert.py: temperature and Lennard-Jones conversion utilities (CLI: fl-C2K, fl-K2C, fl-C2F, fl-F2C, fl-F2K, fl-K2F, fl-eps2K)

      • plotting.py: command-line wrappers around the functions in utils/plotting.py (CLI: fl-plt-comp, fl-plt-props)

      • fuel_manager.py: fuel manager utility

      • decomp_smiles.py: SMILES group-decomposition utility (CLI: fl-decomp-smiles)

      • simulate.py: fuel test simulations with plots of the results (CLI: fl-simulate)

      • build_docs.py: documentation builder utility

      • clean_docs.py: documentation cleaner utility

      • format_code.py: code formatter utility

  • tests: directory containing CI unit tests for FuelLib. The CI test checks if the cumulative error of property predictions of a new proposed model are less than or equal to the current model.

    • baseline_predictions: directory that contains baseline predictions and script generate_baseline.py for generating baseline predictions for CI testing.

    • test_accuracy.py: unit test used in CI for verifying new model predictions preserve accuracy

    • test_source_docstrings.py: documentation contract test that checks public source functions include required docstring fields (:param:, :type:, :return:, :rtype:).

    • test_api.py: combined API/signature and function-evaluation test that checks public fuellib module and class method signatures for unexpected API drift and runs representative FuelLib smoke evaluations.

    • test_cli_utilities.py: unit test for utility functions and CLI commands including temperature conversion and transport property calculations.

    • test_hc_identification.py: unit test for hydrocarbon classification logic.

    • test_gcm_gani.py: unit tests for the gani GCM, including comparison of RDKit SMILES decompositions with ref_gani.csv.

    • test_gcm_nannoolal.py: unit tests for the nannoolal GCM, including comparison of RDKit SMILES decompositions with ref_nannoolal.csv and the Nannoolal viscosity correlations.

    • test_gcm_unifac.py: unit tests for the unifac GCM, including comparison of RDKit SMILES decompositions with ref_unifac.csv and checks of the UNIFAC 2.0 activity coefficients.

    • test_cli_decomp_smiles.py: unit tests for the fl-decomp-smiles command.

  • tutorials: directory containing example scripts that demonstrate how to use FuelLib

    • basic.py: example script that demonstrates basic usage of FuelLib

    • hefa_blends.py: example script that calculates properties of HEFA:Jet-A blends

    • custom_fuel.py: example script that loads a custom fuel from a user-provided data directory

Public API

FuelLib’s public API is continuously validated in CI using tests/test_api.py. This test verifies expected public module/class signatures and runs representative FuelLib smoke evaluations to catch unintended behavior changes.

The project aims to keep the public API stable across releases. Any intentional breaking API change should be explicitly documented in release notes and accompanied by updates to tests and user-facing documentation.
